# Frontend

Next.js (App Router) + React + TypeScript + Tailwind v4, managed with `pnpm`. Desktop web only. Contracts are in [PROTOCOL.md](../PROTOCOL.md).

This Next.js version differs from most training data. Read the relevant guide in `node_modules/next/dist/docs/` before using a Next API (see the block in `AGENTS.md` here).

## Visual language

One look on every screen: a charcoal arena with chicken-comb red for action, a condensed display face for anything competitive, and restrained depth and motion. `globals.css` holds every token; components use them through Tailwind (`bg-surface`, `text-ink-muted`, `rounded-panel`, `shadow-raised`, `text-3xl`, `duration-(--duration-fast)`), never raw hex.

**Audit (US 14).** Every screen was checked against a "generic / AI-generated" list. Found and removed: gradient panels (the old card recipe), a ✓ glyph standing in for state, meaningless dots (badge bullets, the "generating" pulse, glowing online dots), decorative ring artwork, uneven panel padding (p-4 to p-9), and unclear button hierarchy (several red buttons per view, Block styled like Add friend). No colored left borders were found; none may be added.

**Tokens** (`:root` and `@theme` in `globals.css`):

| Role | Tokens | Use |
|---|---|---|
| Surfaces | `canvas`, `surface`, `surface-raised`, `inset`, `line`, `line-strong` | Page, panels, hover/raised, recessed areas and inputs, hairlines |
| Ink | `ink`, `ink-muted`, `ink-faint` | Body, secondary, faint text; faint still passes 4.5:1 |
| Action | `accent`, `accent-hover`, `accent-press`, `accent-ink`, `accent-wash` | Primary fills; red text on charcoal; translucent highlight (active nav, your row) |
| Meaning | `side-pro`, `side-con`, `win`, `loss`, `danger`, `gold`, `silver`, `bronze` | Side labels and rings (never large fills); results; errors; podium and streaks |
| Type | `text-xs` … `text-7xl` | One 1.2 ratio, fluid with `clamp()` (17 px base at 1440 px wide; body steps shrink to 15.5 px and display steps to 13.5 px at 360 px). rem-based, so zoom scales it |
| Fonts | `font-sans` (Geist), `font-mono` (Geist Mono), `font-display` (Barlow Condensed via `next/font`) | Display face for headlines, Elo, ranks, timers, and stats |
| Spacing | Tailwind's 4 px grid, plus `gutter` (page sides), `panel` (panel padding), `stack` (gaps between panels) | `px-gutter`, `p-panel`, `gap-stack` |
| Corners | `rounded-control` (12 px), `rounded-inset` (16 px), `rounded-panel` (24 px), `rounded-full` | Never `rounded-md`/`rounded-lg` |
| Depth | `shadow-raised`, `shadow-overlay`, `shadow-button`, `shadow-pressed` | Inner top highlight plus soft elevation; overlays are dialogs and popovers |
| Motion | `--duration-instant/fast/base/slow/reveal`, `ease-out`, `ease-in-out`, `--ease-overshoot`; `animate-rise/fade/pop/shimmer` | Hover and press 90–150 ms, entrances 220–420 ms, reveals up to 700 ms |

**Utilities** (`@utility` in `globals.css`): `panel` (surface, hairline, panel corners, raised depth), `well` (recessed area), `headline` (display face, uppercase), `stat` (display face with tabular, lining numbers, so Elo and timers line up in columns), `eyebrow` (small uppercase label), `focus-ring` (2 px ink outline on `:focus-visible`), and the `interactive:` variant (not `disabled`, not `aria-disabled`) for hover and press styles.

**Shared components.** `button.tsx` (`primary`, `secondary`, `ghost`, `danger` in `sm`/`md`/`lg`; `buttonClass()` and `linkClass` for links): one primary per view; hover lightens while preserving white-label contrast of at least 4.5:1, press nudges down 1 px and to 98% scale, focus shows the ring, disabled and `aria-disabled` fade to 45% and stop reacting. `modal.tsx` is the only modal, on native `<dialog>` (`busy` refuses Escape while a request runs, `blocking` always). `popover-menu.tsx` is the header's profile menu on the native `popover` attribute (click, hover with a mouse, Escape and outside clicks close it). `page-header.tsx` tops every signed-in screen (eyebrow, display title labelling `<main>`, description, actions). `skeleton.tsx`, `empty-state.tsx`, and `error-state.tsx` are the only loading, empty, and error states. `count-up.tsx` counts numbers (Elo changes). `face-off.tsx` shows both players and their sides. `page-transition.tsx` wraps page bodies (below).

**Motion.** Animate only `transform` and `opacity`; transitions may also change colors and borders. The compact header search may transition width over 220 ms to reveal the input without scaling its text. Page changes use the View Transitions API through React's `<ViewTransition>` (`page-transition.tsx`, inside `AppShell` and the arena): the old page fades up and out, the new one rises in, while the header and sidebar (`view-transition-name` `site-header`/`site-sidebar`) hold still. `prefers-reduced-motion` turns every animation, transition, and view transition off, and `CountUp` jumps to its final value.

**Do not:** add light mode; use gradients or large colored fills (no purple/indigo/blue "AI" gradients); add glows or shadows outside the depth tokens; use emoji, decorative icons, or status dots (say the status in words); add colored left (or top) borders as accents; add fonts beyond the three above; add a component library (shadcn, MUI, etc.); write raw hex or zinc classes in components; add a second modal, button, or loading/empty/error pattern. Small line icons on lobby cards and in the sidebar are allowed.

## Usability

- Design for desktop and keep primary actions usable on phones and at 200% zoom. Reflow the shared header and navigation down to 320 px without horizontal scrolling.
- Every data view has loading, empty, and error states, using `skeleton.tsx`, `empty-state.tsx`, and `error-state.tsx` (with a retry where one makes sense). Copy is short.
- Status changes use `aria-live="polite"`. Streaming model text and second-by-second countdowns do not; countdowns use `role="timer"`.
- Every control is keyboard reachable with the focus style above. Headings via `aria-labelledby` on sections.
- Show deadlines as live countdowns from the server's `deadline`; never trust a local timer as authoritative.
- Model output and prompts render as plain text (`whitespace-pre-wrap`). Never `dangerouslySetInnerHTML`, never Markdown.
- Copy is short and plain. "Match" in code, "debate" in UI.

**Homepage (`/`).** The primary card loads the arena catalog and offers Quick Queue, a specific cloud model, or Bring your own model. Quick Queue is the default for a new player and lets matchmaking assign a model. The last available selection is remembered in the browser. The model picker uses a native popover with arrow keys, Home/End, typeahead, Enter/Space, Escape, Tab, and outside dismissal. The model and author appear separately. `model-brand.ts` maps `provider_slug` and `model_slug` to local SVGs, with display-name prefixes for older servers and a neutral chip for unknown authors. Quick Queue uses a bolt. Logos and attribution live in `public/model-logos/`.

BYOM offers the player's paired devices with model, size, and availability. Only idle devices can join. The form links to device setup when none are paired. Device errors refresh the list and an unavailable arena refreshes the catalog. Loading, empty and error states on the catalog block new joins independently of queue recovery and cancellation. Today's challenge shows the full topic and twist beside matchmaking. Recent points and results link to debate history.

**Matchmaking status.** The signed-in `QueueProvider` checks for an existing entry before registering one, polls in sequence each second while queued, and recovers the mode, model and elapsed time from the server across navigation and reloads. Play shows status inline. Other signed-in pages show a queue card inside the existing header row. Its status area shows a rotating ring while searching, the model or queue type, and elapsed time. The model name drops the provider prefix and truncates to the space available. Reduced motion makes the ring static. The Cancel button sits directly to the right of the status. Selecting the status opens a popover with the full arena label and retry when needed. The header sticks while the card is present. On narrow screens the card takes the wordmark’s place and Play remains in Menu. At phone widths under 400 px the search control uses its icon while the card is visible. Daily Challenge uses the same header after a join. Selection is locked while a queue operation is active. A new assignment opens the arena from any of these pages, including when pairing beats a cancellation. After a player returns from an already visited arena, the UI waits for that assignment to clear before allowing a new queue. Older servers without queue metadata start elapsed time when the browser first observes the queue.

**Auth pages.** `/login` and `/signup` share `auth-layout.tsx`. Both are public: `SessionProvider`'s `PUBLIC_PATHS` lists them, or it would redirect signed-out visitors away from signup.

**Daily challenge freshness.** The lobby and challenge page share a loader that refetches at the server's UTC reset and when the tab becomes visible. An expired challenge is cleared while the new day loads.

**Automatic sign-in.** Sessions live in the backend's HTTP-only cookie, never in local storage. `/` and `/login` are Server Components that call `serverSession()` (`lib/server-session.ts`), which asks `GET /auth/me` to validate the cookie: `/` redirects to `/login` when there's no valid session, and `/login` redirects to `/` when there is. If the backend is unreachable, both pages render and show their error states. `SessionProvider` also sends the visitor to `/login` whenever its own `/auth/me` check or a logout leaves the session signed out, except on `/login` and `/health`. Server-side fetches forward the browser's raw `Cookie` header via `forwardedCookie()`: `cookies().toString()` URL-encodes values and breaks the signed cookie.

**App shell and sidebar (`app-shell.tsx`, `sidebar.tsx`).** Signed-in pages share labeled links for Play, Daily challenge, Leaderboards, Debate tips, Local models, Debate history, Profile, and Settings. Desktop shows them in a sidebar. Below `lg`, a labeled Menu in the header opens the same links and How to play. It supports touch, keyboard, Escape, and outside dismissal. Profile links to the signed-in player's tag or `/profile/me` and shows the pending friend request count. Admin appears for admins only. The current destination has `aria-current`. Navigation closes the menu and focuses the destination body, the same target as Skip to content. Login, signup, and the match arena use separate layouts.

**Header (`site-header.tsx`).** Shared by the lobby, search, and profile: wordmark, one persistent How to play dialog entry, player search, and the profile menu (`popover-menu.tsx`: hover, click, keyboard) with My profile (same destination as the sidebar), Settings and Sign out. Identity comes from `useSession()`, with guest/loading/error states.

**Leaderboards (`/leaderboards`).** The arena selector lists active provided model ladders and BYOM from `GET /v1/ladders`. The top three stand on a podium (first raised in the middle, gold/silver/bronze rank numbers, Elo and record); the table below shows rank, player, and Elo from fourth place. Your own entry is highlighted. It loads 20 entries first and appends more as the bottom of the table comes into view, up to 50. Switching ladders clears the previous table and cancels its requests. Only the page body scrolls; the header and sidebar stay in place.

**Tag dialog (`tag-dialog.tsx`).** Shown by the lobby if and only if the signed-in user's `tag` is null. It claims the tag with `PUT /v1/users/me/tag`. It is a blocking modal: Escape and closing are refused, and the only ways out are claiming a tag or signing out. The input checks the format rule locally on every keystroke, and after a 350 ms pause asks `GET /v1/users/username-availability` (aborting stale requests) for taken/profanity results. Submit stays disabled while the format is invalid or the tag is known to be unavailable; `PATCH /v1/users/me` rejections are shown inline. Copy warns that the tag can't be changed.

**Player search (`user-search.tsx`).** The desktop magnifier expands into a focused combobox. On narrow screens a labeled Search button opens a full-width field below the header. Escape or Close returns focus to the trigger. Leaving the search collapses it and preserves the query. After 200 ms, the open list fetches up to five suggestions and cancels stale requests. Arrow keys highlight players. Enter opens the highlighted profile or the full results, also available from See all results. The list announces searching, empty states, and errors. The results page loads 20 at a time and shows a prompt for a blank query.

**Settings (`/settings`).** Username and email have visible Edit actions; the picture has an Edit profile picture button. These open their respective dialogs. The picture sits beside the account details, and the permanent tag is read-only. `profile-editor.tsx` updates the username or email with `PATCH /v1/users/me`, with labelled fields and associated inline validation. The picture editor previews PNG/JPEG/WebP up to 2 MB, identifies the selected file, and uploads raw bytes to `PUT /v1/users/me/avatar`. Removing an uploaded picture restores initials until the next Google sign-in supplies a picture. Successful edits update the shared session.

**Profile (`/profile/[tag]`).** A Server Component that forwards the session cookie to `GET /v1/users/by-tag/{tag}`. The avatar, username, tag, and own email sit directly on the page background above a full-width Record card. The username is large with the tag beneath; search results, suggestions, and friends lists do the same, and the header and arena show the username. `displayName()` (`lib/protocol.ts`) falls back to the tag for users without a username. 401 redirects to `/login`; an unknown or malformed tag shows "Player not found"; other failures show "Profile unavailable". It shows only `UserProfile` fields, plus your own email on your own profile (from `/auth/me`, marked "only you can see this"). `avatar.tsx` shows uploaded pictures from the backend with `unoptimized`, so the browser sends the session cookie that route requires. On other players' profiles, `add-friend.tsx` starts from `is_friend` and `friend_request` and shows Add friend, Cancel request, Accept and Decline, or Remove friend, with inline errors, including a wait message on 429; it's keyed by player so its state can't carry over to the next profile. Beside it, `block-button.tsx` starts from `is_blocked` and shows Block or Unblock (`PUT`/`DELETE /v1/block/{id}`) with inline errors; after each change it refreshes the page and the friend request count, since blocking ends friendships and requests. While you've blocked a player, Add friend is hidden. A profile whose owner blocked you (`read_blocked`) shows "You have been blocked from this profile." and the block button instead, so you can block back or lift your own block. On your own profile, the Friends panel lists your first 100 friends from `GET /v1/friends`, with empty and error states. When there are pending requests, a compact notice in Friends expands to show up to 100 each way. `friend-requests.tsx` offers Accept and Decline for incoming and Cancel for outgoing, and refreshes the page after each answer. Below it, `blocked-players.tsx` is a collapsed `<details>` panel listing the 100 players you blocked most recently (`GET /v1/block`), with the count in its summary and an Unblock button on each that refreshes the page. The Record card shows rank (gold, silver, or bronze for the top three), points, best current Elo across ladders, and streak in the display face, then win rate, debates, wins, and losses, summed from `ratings`; it shows "No debates yet." while there are none. `avatar.tsx` renders Google avatars (the only host in `next.config.ts`) and falls back to initials.

**Match history (`/matches`, `/matches/[match_id]`).** `match-history.tsx` lists `GET /v1/users/{id}/matches` for the signed-in player, 20 at a time with Load more, and each row opens `match-detail.tsx` (`GET /v1/matches/{id}`). Rows separate the topic, opponent, side/model, Elo and date, with a visible View debate cue and newest-first count above the list. Labels, side names and colors (`SIDE_LABEL`, the one place to change for another "vs" pair), and Elo formatting live in `lib/matches.ts`. Each row's Elo change counts up from 0. Arguments are model output, so they render as plain text with `whitespace-pre-wrap`. Someone else's match, or a bad ID, shows "Debate not found". The sidebar highlights Debate history on these pages.

**Game selection (`/play`).** A card listing ladders (cloud models and the BYOM arena), each showing your Elo on it. BYOM requires choosing one of your online devices; offline devices are shown but disabled with a link to `/bilc`. One primary "Find match" button. While queued: elapsed time and a secondary "Cancel". On `matched`, navigate to `/match/[match_id]`.

**Debate view (`/match/[match_id]`).** A two-second Match found reveal introduces both players, their sides and ratings, and the topic. It fades into the prompt view and dismisses on pointer or keyboard interaction or when a control receives focus. With reduced motion, players go directly to the prompt view, which keeps a compact matchup. The server-provided model name, assigned position, deadline, and any daily twist sit beside the editor. On phones the submit row sticks to the bottom as needed. The prompt goes to the argument model on the cloud inference service or the player's device. The judge and opponent see generated arguments, which can echo the prompt. A rejected prompt returns focus to the preserved draft. If the server closes the prompt window, the draft remains available to copy.

The sticky header announces the current match phase, including waiting, judging, and connection loss. Streamed text stays outside the live region. When the edit form becomes the transcript, focus moves to the argument heading. Results focus the outcome and show the reason before ratings and argument tabs. A no-show result can appear before the initial topic arrives. The player's submitted prompt stays in page memory and appears only in their argument tab. **Leave debate…** opens the forfeit dialog. Confirming sends `RESIGN`, waits for the result for up to three seconds, and returns to Play. The header offers a lobby link after a result or a lost connection. Reconnect snapshots remain planned.

**Tips coach.** The transcript scrolls within its panel, following replies only while the reader is near the bottom. A separate status line announces reply progress; streamed text stays outside live regions. Loading failures offer retry. The composer shows keyboard guidance and the remaining character allowance; an oversized draft stays editable. Enter sends, Shift + Enter inserts a line, and IME composition does not send. New chat returns focus to the composer.

## Code conventions

- Routes in `app/<route>/page.tsx`. Server Components by default; add `"use client"` only for state, effects, or browser APIs, as low in the tree as possible.
- Shared components in `app/components/`, one per file, kebab-case filename, default-exported PascalCase component.
- Non-UI code in `app/lib/`: `auth.ts` (`backendUrl`), `api.ts` (one fetch wrapper: `credentials: "include"`, timeout, optional JSON body, parses the PROTOCOL error envelope into `ApiError { status, code, detail }`), `protocol.ts` (TypeScript types mirroring PROTOCOL.md, kept in sync by hand).
- Never hard-code the backend URL; use `backendUrl`. Env vars exposed to the browser must be `NEXT_PUBLIC_*` and must not be secrets.
- A `<form>` rendered before the page's JavaScript loads, with named fields that are private, has `method="post"`, even with an `onSubmit` handler. With no method it submits as GET if used too early, which puts its fields, passwords included, in the URL. `/login` and `/signup` also redirect away any old URL holding a `password`.
- Every fetch/socket/timer is cleaned up on unmount (`AbortController`, `close()`), as in `arena-stats.tsx`.
- Style with Tailwind classes inline. No CSS modules or new global CSS beyond the tokens, `@utility` primitives, and view-transition rules in `globals.css`.

## State (React Context)

- Server data that a single page needs: fetch in a Server Component or local `useState`. No context.
- Context is for state shared across a subtree that changes over time. Contexts:
  - `SessionContext` (app-wide, implemented in `session-provider.tsx`): current user or null, session status, `setUser()`, `refresh()` (re-checks `/auth/me`; the login form awaits it before navigating so the lobby sees the new session), `logout()`. Provider in the root layout. Replaces per-component `/auth/me` calls.
  - `FriendRequestsContext` (app-wide, implemented in `friend-requests-provider.tsx`, inside `SessionProvider`): `count` of incoming friend requests and `refresh()`. Counts while signed in, every 30 s while the tab is visible and on returning to the tab; `friend-requests.tsx`, `add-friend.tsx`, and `block-button.tsx` call `refresh()` after a change. A failed count keeps the last one.
  - `QueueContext` (app-wide, implemented in `queue-provider.tsx`, inside `SessionProvider`): owns queue recovery, polling, registration, cancellation, and navigation to a new match.
  - `MatchContext` (implemented, inside `/match/[match_id]` only): owns one match WebSocket, heartbeat echo and cleanup, a reducer over current PROTOCOL messages, `submitPrompt()`, and `resign()`. No component other than its provider touches the socket.
- One context per concern, in `app/components/providers/<name>-provider.tsx`, exporting the provider and a `use<Name>()` hook that throws outside its provider.
- Keep context values stable (`useMemo`/`useReducer`); put fast-changing streaming text in the reducer, not in many `useState`s.
- No external state libraries.
